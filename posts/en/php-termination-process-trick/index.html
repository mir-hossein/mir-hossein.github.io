PHP termination process time window

Between the occurrence of any factor that leads to execution termination (such as exit/die, uncaught exception, etc.) and complete execution halt, PHP allows other destructors and shutdown functions to run and complete unfinished tasks, such as closing database connections (Except in a few specific cases). This golden window of time is exactly what an attacker needs; Because under suitable conditions, one can still access that object which was the cause of the termination. I named this behavior "PHP-TPTW". ("PHP-Termination Process Time Window").

PHP-TPTW in deserialization

It is very common for developers to use a ‍‍__wakeup method that throws an exception to prevent deserialization, thinking that this is the correct approach. But is this really always the case?

When an (uncaught) exception occurs (or code termination via exit, die, …) inside a __wakeup method, the termination process is initiated. Still an attacker has a time window to use the object with other destructors or shutdown functions in the termination process.

 <?php

 class A {
   function __wakeup() {
     echo "__wakeup is running ...\n";
     throw new Exception("Deserialization of this class is not allowed!");
   }
	
   function foo() {
     echo __METHOD__ . " is running. If you see this message, it means __wakeup can be bypassed! \n\n\n";
   }
 }

 class B {
   public $value;
	
   function __destruct() {
     $this->value->foo();
   }
 }

 unserialize('O:1:"B":1:{s:5:"value";O:1:"A":0:{}}');

Results on PHP 8.5.11 (Sep 2026), PHP 8.x, PHP 7.x, PHP 5.6:

__wakeup is running ...
A::foo is running. If you see this message, it means __wakeup can be bypassed! 


PHP Fatal error:  Uncaught Exception: Deserialization of this class is not allowed! in /tmp/test.php:6
Stack trace:
#0 [internal function]: A->__wakeup()
#1 /tmp/test.php(22): unserialize()
#2 {main}
  thrown in /tmp/test.php on line 6

Method A::foo() has been executed successfully between an (uncaught) exception occurrence and the complete execution halt.

This trick (PHP-TPTW) allows us to bypass __wakeup restriction and use the class members (properties, methods).

Prerequisites:

  • A class whose unserialization capability is restricted by the wakeup method, and using it for unserialization results in an exception or program exit.

  • A destructor or any method or function that executes during the termination process and can access the forbidden class.

For multi-level composition:

If class A contains an instance of class B, class B contains an instance of class C, class C contains an instance of class D, class D contains an instance of class E: (An instance of a class = object)

  • __wakeup will be called in this order: E→D→C→B→A.

    • If inside __wakeup we encounter an exception/exit, the continuation of __wakeup process will be stopped (will not trigger other __wakeup methods) but objects will be exist; Then:

  • __destruct will be called in order of top-level classes to lower-level classes. A→B→C→D→E.

    • Destructors of top-level classes will be called only if they haven’t __wakeup method. ← Important note.
    • Destructor of the class that caused an Exception will NOT be called. ← Important note.
    • Destructors of lower-level classes will be called whether they have __wakeup method or not. ← Important note.

Besides Composition, there are other ways to use PHP-TPTW trick.

  • PHP-TPTW trick works on PHP 5.6, 7.x, 8.x. (I didn’t test on older than PHP 5.6).

  • PHP-TPTW trick is based on a native PHP behavior and will NOT be fixed in the near future. (IMO)

  • PHP-TPTW trick is NOT only for deserialization (__wakeup/‍‍‍__unserialize bypass) but also HAS other applications.

Conclusion

This blog post only shows the security aspect of a native PHP behavior by demonstrating a (new?) __wakeup bypass for a very popular library after years. The issue (POP chain) has been solved on Guzzle 8.0 and Psr7 3.0. (Released 2026 Jul 20)

  • You can find new POP chains by using PHP-TPTW trick.

  • Don’t trust __wakeup to prevent deserialization.

  • __wakeup has been soft deprecated. (PHP >= 8.5)

  • __unserialize can only be bypassed with PHP-TPTW if the corresponding properties are set before to exit/exception. (Or default values). (PHP >= 7.4)
