(Re?)-introducing several PHP tricks

Trick #1: PHP-IAA

PHP and some other languages (JavaScript, …) are not strict on arguments count for user defined functions/methods, but are strict on arguments count for build-in functions/methods.

The minimum number of arguments to call a “user defined” function/method is the number of required parameters and a user can call it with the minimum arguments or more. Please note that the data type of arguments and (required) parameters must be matched, but for additional arguments is not necessary because there is no parameter to be matched. PHP team knows that and they don’t want to solve the problem. [RFC:strict_argcount]

I named this behavior "Ignoring Additional Arguments" or "PHP-IAA". This behavior allows us to use it as a very useful trick.

e.g.: For a function like that:

function printHello()
{
  echo "Hello!";
}

The function is callable with 0, 1, 2 or more arguments, without any warning or notice.

printHello();                       // Displays "Hello!" without any notice/warning/error.

printHello("arg1");                 // Displays "Hello!" without any notice/warning/error.

printHello("arg1", "arg2");         // Displays "Hello!" without any notice/warning/error.

printHello("arg1", "arg2", "arg3"); // Displays "Hello!" without any notice/warning/error.

...                                 // Displays "Hello!" without any notice/warning/error.

Also in an arbitrary function call with a specific number of arguments, it can be replaced with another user-defined function/method that has fewer parameters.

e.g.:

$func($arg1, $arg2);

Can be used to call a user-defined function with 2 or 1 or 0 parameter(s).

Tip:

Parameter-less [user-defined] functions/methods are the best options to use with PHP-IAA trick.

  • It’s possible to call them with any number of arguments. (Almost always)
  • There is no parameter, and there is no need to worry about data type issues.
  • There is no parameter, and there is no need to worry about what happens to a parameter inside a function/method … (context dependent)

Note:

  • PHP-IAA trick works on PHP 4, 5.x, 7.x, 8.x.
  • PHP-IAA trick is simple and easy.

Tip:

  • To call Build-in functions/methods, sometimes a combination of call_user_func and call_user_func_array is useful.
  • The above tip is also useful for user-defined functions/methods specially when you have problem with default values of parameters.

Let’s use the trick practically …

Guzzle

“Guzzle is a PHP HTTP client that makes it easy to send HTTP requests and trivial to integrate with web services.” source

According to Packagist statistics, Guzzle is the eighth most popular library (Total installs) and has been installed more than 1,000,000,000 times to date.

The list of some dependents can be found at this link, e.g.: Drupal, Laravel, Magento2, typo3/cms-core, shopware/core, craftcms/cms, aws/aws-sdk-php, google/auth, google/cloud, microsoft/azure-storage-common, shopify/shopify-api, ovh/ovh, some popular Wordpress plugins (For e.g.: Yoast SEO is the #2nd most popular plugin for Wordpress) and more …

Since the end of 2018 (more than 7 years ago), no RCE GC for Guzzle has been [publicly] available; During these years, only one File-Write GC was available, which had limitations in the operational environments.

Some of the limitations of File-write GCs:

  1. If the gadget starts from __destruct magic method, probably the problem of absolute path can occur.

  2. The path MUST be writable.

  3. The path MUST be accessible. (directly or indirectly via loader or …).

  4. The file name extension MUST be .php or …

  5. The file content may be blocked by WAF.

  6. An anti-shell may remove it, if present.

In these cases, a direct RCE is usually better.

  private function pump(int $length): void
  {
    if ($this->source !== null) {
      do {
        $data = ($this->source)($length);
        if ($data === false || $data === null) {
          $this->source = null;

          return;
        }
        $this->buffer->write($data);
        $length -= strlen($data);
      } while ($length > 0);
    }
  }

  public function resolve(): callable
  {
    if ($this->cached === null) {
      if (($prev = $this->handler) === null) {
        throw new \LogicException('No handler has been specified');
      }

      foreach (\array_reverse($this->stack) as $fn) {
        /** @var callable(RequestInterface, array): PromiseInterface $prev */
        $prev = $fn[0]($prev);
      }

      $this->cached = $prev;
    }

    return $this->cached;
  }

Line #216: resolve method is parameter-less and must return a callable.

Line #219: $prev value will be set from $this->handler and we can control it.

Line #225: $prev=$fn[0]($prev); is an arbitrary function call in a loop and the result of the function call will be used for the next function call as an argument. (function composition)

Here we can call system("id"); or another arbitrary function. After the function call, we will face three problems that we need to find solutions for:

  • Type-error: resolve must return a callable. (Guzzle >= 7.0.0-beta.1)
  • 1MB Data: We need to return 1,048,576 bytes. (In one iteration or more)
  • File write issue: Guzzle will try to write a file (from save method).

As told above, for the next iteration, the result of the previous function call will be used as argument and we CAN NOT GUESS the result of some function calls. (e.g.: reading a file content …); A solution is something like that: system("command; echo the_value_we_want"); but it’s not good enough; In a hardened environment, system and other related functions are disabled and we can’t use them.

Trick #2: PHP-IAA-RDV
Is there a function/method that accepts any value as an argument and returns what we want?

It’s PHP and almost everything is possible. By using PHP-IAA trick and calling a getter (or non-standard getter) method, we can ignore the argument(s) and return a desired value from a property.

Note:

  • getters or non-standard getters are (almost) parameter-less methods.
  • __toString() method is (sometimes, almost) a getter.

When we encounter a complex object, array, or unwanted value as argument(s), PHP-IAA trick is useful to ignore it(them) and return a desired value. I named this trick PHP-IAA-RDV (Ignoring Additional Arguments - Returning a Desired Value), which is a special case of PHP-IAA.

By using the trick, we will fill $prev with our arbitrary value to be used as an argument for the next function call.

Trick #3: PHP-ISCE

To stop a running code, we can use set_exception_handler function and trigger it by calling a non-existent function.

  • For PHP >= 8.4.0 a solution is exit function. (die is an alias for exit)

I named this trick "Intentional Stopping of Code Execution" or "PHP-ISCE".

  • PHP-ISCE trick works on PHP 7.x and 8.x.

  • If __toString() is used while PHP-ISCE is being used, it will work on PHP >= 7.4.

    • For PHP <= 7.3 throwing an exception from __toString() is not allowed.

Exploiting function composition

The numbers indicate the n’th iteration in the loop.

  1. Arbitrary function call with arbitrary argument.
    • If you DON’T need a clean exit, other steps are NOT necessary.
  2. Call a getter (PHP-IAA again) to fill $prev with is_int or other suitable method/function.
  3. Call set_exception_handler("is_int"). This will set is_int function as an exception handler. (PHP-ISCE)
  4. Call a non-existent function (like "1") to trigger the exception handler and stop the execution. (PHP-ISCE)
    • Completely clean exit: (PHP >= 7.4)
      • Without any notice/warning/error.
      • Without any file creation.
      • Without printing any unwanted string in the output after it.
    • (PHP <= 7.3)
      • Will work but after a successful execution, an error will occur. (PHP <= 8.1 have reached end of life.)

Conclusion

PHP-IAA is based on a native PHP behavior and will NOT be fixed in the near future. This trick is NOT limited to deserialization only and has broader applications.

Please use it only for good purposes. I shared it to inform defensive teams and to document the trick, NOT to annoy people.

Most PHP developers know about PHP-IAA; This blog post only shows the security aspect of an obvious concept by demonstrating a new RCE GC for a popular library with over 1,000,000,000 installs after +7 years.

The issue (POP chain) has been solved on Guzzle 8.0. I’m happy that I was able to take even a small step toward improving the security of this library.
